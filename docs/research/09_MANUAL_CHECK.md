# 下一步：首次真实采集检查

代码、自动测试和导出分析已就绪。下面需要用户亲自完成，因为涉及系统屏幕/音频访问权限和主观活动标签。不要为了测试开启麦克风；本功能只分析电脑播放的声音。

## 先做一个短检查，不需要全天录制

1. 退出正在运行的旧版 Desktop Buddy，打开本次提供的 Release 测试版。
2. 点击菜单栏宠物，打开活动日记开关；分别启用屏幕分析和播放声音分析。如果 macOS 弹出系统权限提示，请阅读后自行决定是否允许。可能需要到系统设置的隐私与安全性页面授予屏幕/系统音频录制权限，并重启应用。重启后各采集开关需重新开启。
3. 用一个非敏感的代码窗口持续约一分钟，随后播放一段你知道内容的视频或音乐约一分钟。不要把真实会议或私人聊天作为首次测试内容。
4. 回到宠物面板，检查屏幕/声音状态有没有明确失败。点击 Review recent task interval，为所显示的固定时段回答实际活动；不确定就选 Not sure 或跳过。可重复 2–3 次，不要为了得到正确结果修改答案。
5. 关闭屏幕、声音和日记开关，确认没有继续运行采样。首次试用不必开启暂定统计；想查看估计时长时可另行开启 Record tentative activity estimates。
6. 点击 Export diary locally…，保存到项目的 research-data 文件夹，文件名例如 desktop-buddy-diary.json。完成后在聊天里说“已导出”。不需要把原始屏幕或音频发送给任何人。

如果无法看到选项、权限反复提示、声音状态一直未知或程序无响应，只需告诉我具体状态文字。未知不等于故障，也不能直接判定没有声音；需要结合已知测试片段排查。

## 验证边界

- 自动测试不会替用户授予权限，也不证明真实捕获成功。
- 反馈是用户自述，界面中可见的系统猜测可能影响答案；初步结果只能用于调试。
- 区分暂定估计、用户标注、未知和可能离席。不声称识别真实心理专注。
- 已有一次非受控进程 CPU/RSS 观察；不是屏幕/声音开关条件的对照，不可用来证明传感器功耗。
- 个人导出和测量数据仍被 git 忽略，不上传 GitHub。
